# __PROJECT_NAME__

Generated by the **AET Agent Project Scaffolder** from the **langgraph-rag** template using the __PROVIDER__ mode.

This is an actually runnable, local-first **retrieval-augmented generation (RAG)** reference application. A LangGraph workflow performs BM25 lexical retrieval over local JSONL knowledge passages and then generates an evidence-based answer. Offline mock mode returns the retrieved passage verbatim as a **deterministic demonstration, not an LLM response**. Optional Ollama mode performs real local model synthesis over the retrieved evidence. No hosted embeddings or cloud APIs are required.

**Not for public deployment:** this app is unauthenticated, has no authorisation, and no production-grade prompt-injection protection. Source passage text is untrusted, and model answers may be incorrect or insufficiently grounded.

## Requirements and quick start

Python 3.11+ (native Windows or Linux), with no Docker, WSL or cloud account:

~~~powershell
python -m pip install -e ".[dev]"
python -m pytest -q
python -m uvicorn app.main:app --reload
~~~

Open http://127.0.0.1:8000/docs. Call **POST /ask** with:

~~~json
{"question": "What is the sample return policy?"}
~~~

The default mock response includes actual evidence from the fabricated local return policy and a source ID. A question with no matching corpus terms returns a clear no-evidence response and an empty source list. **GET /health** checks that the web application responds, not that a model is available.

## Knowledge and retrieval

Synthetic starter records are in data/knowledge.jsonl; each line is JSON with string fields id and text. Records and source identifiers are validated and bounded (200 documents, 1 MB total; each passage at most 4,000 characters). The built-in BM25 lexical retriever ranks passages by keyword relevance and excludes zero-overlap results. It is not a semantic embedding retriever, and there is no claim of multilingual or semantic retrieval quality.

To build a new index from **approved, non-confidential** local Markdown or text documents:

~~~powershell
python -m app.ingest --input my-documents --output data/my-knowledge.jsonl
~~~

The input directory must exist and contain at most 30 non-symlink UTF-8 .txt/.md files. Ingestion deterministically chunks the documents and creates a new JSONL file, refusing to overwrite existing files. Then set **AET_KNOWLEDGE_PATH=data/my-knowledge.jsonl** in your local .env. Do not ingest credentials, secrets, client records or confidential documents in this reference app.

## Optional local Ollama inference

1. Install Ollama separately and download the __OLLAMA_MODEL__ model if permitted.
2. Copy .env.example to .env and set **AET_PROVIDER=ollama**.
3. Ensure the model is available at http://127.0.0.1:11434 (loopback-only).
4. Restart the generated application and call POST /ask.

Automated tests inject fake Ollama transport: CI downloads no model and makes no paid API calls. If Ollama is unavailable, the API returns a sanitised HTTP 503 error. The system prompt asks for source-grounded answers with citations, but this is **instruction only**, not a correctness or prompt-injection guarantee.

## Design boundaries

- Pure-Python BM25 + LangGraph StateGraph retrieval/respond nodes, no AEA dependency.
- No remote providers, internet search, managed vector stores, authentication or telemetry.
- Test fixtures use fabricated policies. AET does not assert that any shipping, return or support policy applies to a real organisation.
- The corpus reader is bounded and rejects symlink files; it is a local developer tool, not a hardened multi-tenant ingestion service.
- The .aet-template.json file identifies the template for the read-only project doctor.
