# __PROJECT_NAME__

Generated by the **AET Agent Project Scaffolder** from the **langgraph-rag** template using the __PROVIDER__ mode.

This is an actually runnable, local-first **retrieval-augmented generation (RAG)** reference application. A LangGraph workflow performs BM25 lexical retrieval over local JSONL knowledge passages and then generates an evidence-based answer. Offline mock mode returns the retrieved passage verbatim as a **deterministic demonstration, not an LLM response**. Optional Ollama or cloud modes perform model synthesis over retrieved evidence. Mock mode needs no hosted embeddings, cloud API or credentials.

**Not for public deployment:** this app is unauthenticated, has no authorisation, and no production-grade prompt-injection protection. Source passage text is untrusted, and model answers may be incorrect or insufficiently grounded.

## Requirements and quick start

Python 3.11+ (native Windows or Linux), with no Docker, WSL or cloud account:

~~~powershell
python -m pip install -e ".[dev]"
python -m pytest -q
python -m uvicorn app.main:app --reload
~~~

Open http://127.0.0.1:8000/docs. Call **POST /ask** with:

~~~json
{"question": "What is the sample return policy?"}
~~~

The default mock response includes actual evidence from the fabricated local return policy and a source ID. A question with no matching corpus terms returns a clear no-evidence response and an empty source list. **GET /health** checks that the web application responds, not that a model is available.

## Knowledge and retrieval

Synthetic starter records are in data/knowledge.jsonl; each line is JSON with string fields id and text. Records and source identifiers are validated and bounded (200 documents, 1 MB total; each passage at most 4,000 characters). The built-in BM25 lexical retriever ranks passages by keyword relevance and excludes zero-overlap results. It is not a semantic embedding retriever, and there is no claim of multilingual or semantic retrieval quality.

To build a new index from **approved, non-confidential** local Markdown or text documents:

~~~powershell
python -m app.ingest --input my-documents --output data/my-knowledge.jsonl
~~~

The input directory must exist and contain at most 30 non-symlink UTF-8 .txt/.md files. Ingestion deterministically chunks the documents and creates a new JSONL file, refusing to overwrite existing files. Then set **AET_KNOWLEDGE_PATH=data/my-knowledge.jsonl** in your local .env. Do not ingest credentials, secrets, client records or confidential documents in this reference app.

## Optional local Ollama inference

1. Install Ollama separately and download the __OLLAMA_MODEL__ model if permitted.
2. Copy .env.example to .env and set **AET_PROVIDER=ollama**.
3. Ensure the model is available at http://127.0.0.1:11434 (loopback-only).
4. Restart the generated application and call POST /ask.

Automated tests inject fake Ollama transport: CI downloads no model and makes no paid API calls. If Ollama is unavailable, the API returns a sanitised HTTP 503 error. The system prompt asks for source-grounded answers with citations, but this is **instruction only**, not a correctness or prompt-injection guarantee.

## Design boundaries

- Pure-Python BM25 + LangGraph StateGraph retrieval/respond nodes, no AEA dependency.
- Cloud chat models are optional; no internet search, managed vector stores, authentication or telemetry.
- Test fixtures use fabricated policies. AET does not assert that any shipping, return or support policy applies to a real organisation.
- The corpus reader is bounded and rejects symlink files; it is a local developer tool, not a hardened multi-tenant ingestion service.
- The .aet-template.json file identifies the template for the read-only project doctor.

## M14 application foundations

New projects include `app/foundation.py` with a server-issued `X-Request-ID` and one JSON request log per request. Logs include only request method, fixed route category, status code and duration. **Prompts, generated answers, auth headers, query strings, client addresses, exception strings and unknown URL paths are not logged.** Use `AET_LOG_LEVEL` in `.env` to select DEBUG, INFO, WARNING or ERROR (default INFO).

`GET /health` verifies process liveness. `GET /ready` verifies the local mock mode and applicable local dependencies. It **returns 503 for live model providers** because a network call, credentials and account entitlements are not verified by this developer template. A 503 is not evidence that the live provider itself is down.

A generated `.github/workflows/ci.yml` runs offline tests on Python 3.12. A non-root Docker reference is included, with `.dockerignore` excluding environment files and local build artifacts:

~~~powershell
docker build -t aet-demo-app .
docker run --rm -p 127.0.0.1:8000:8000 aet-demo-app
~~~

The example container runs `AET_PROVIDER=mock` and must be **bound to localhost only**. Never deploy it publicly as supplied: these apps have no authentication, tenant isolation, ingress policy, network egress controls, secrets management or deployment-specific authorisation. For production adoption, teams must add and review these separately.

## M16: Optional framework-native cloud chat providers

Choose a provider at scaffolding time (`--provider openai`, `azure-openai`, `anthropic` or `bedrock`) or update `AET_PROVIDER` in your generated `.env`. No provider connection or credential is needed to generate, run mock tests or use the deterministic tool/retrieval route. Cloud inference is **opt-in, billable and sends prompt content to the selected provider**; do not send client or confidential content without approval.

Install only the required provider integration before invoking its live model:

| Provider | Install | Configuration | Authentication |
| --- | --- | --- | --- |
| OpenAI | `pip install -e ".[openai]"` | `AET_OPENAI_MODEL` | `OPENAI_API_KEY` |
| Azure OpenAI | `pip install -e ".[azure-openai]"` | `AET_AZURE_OPENAI_DEPLOYMENT`, `AET_AZURE_OPENAI_ENDPOINT`, `AET_AZURE_OPENAI_API_VERSION` | `AZURE_OPENAI_API_KEY` |
| Anthropic | `pip install -e ".[anthropic]"` | `AET_ANTHROPIC_MODEL` | `ANTHROPIC_API_KEY` |
| AWS Bedrock | `pip install -e ".[bedrock]"` | `AET_BEDROCK_MODEL_ID`, optional `AET_AWS_REGION` | AWS SDK credential chain (IAM role, SSO/profile, environment) |

For example, use `AET_PROVIDER=openai` and configure a model identifier in `AET_OPENAI_MODEL`. Use a secret manager or injected process environment for credential variables, not checked-in files. `AET_MODEL_TIMEOUT_SECONDS` and `AET_MODEL_MAX_RETRIES` control OpenAI/Azure/Anthropic calls; Bedrock uses AWS SDK client defaults. All provider packages are optional so default installation remains local/offline; selecting an uninstalled provider gives a sanitised HTTP 503 until the corresponding extra is installed.

**Limitations:** This is still a developer starter without authentication, tenant isolation, external egress policy, token budgets or rate limiting. Provider-side availability, permissions, model support, AWS region, billing, safety and credentials must be validated by the adopting team. Cloud tests use injected fakes, never paid inference. No cloud mode is considered ready by the `/ready` endpoint without an external operational check.
